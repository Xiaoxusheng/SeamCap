# 03 · 前端开发文档

> 项目：义乌无痕棒球帽源头工厂外贸独立站（SeamCap）
> 前端形态：**原生 HTML5 / CSS3 / JavaScript**，零框架、零商业模板；首屏由 Go 服务端渲染（SSR），JS 仅做渐进增强。

---

## 1. 渲染架构（重要约定）

为满足 SEO 要求（需求 5.8），前台页面**不采用纯 JS 动态生成内容**：

```
Go html/template 渲染完整 HTML（含产品数据、SEO meta）
        │
        ▼ 浏览器加载后
JS 渐进增强：搜索/筛选/加载更多走 fetch('/api/v1/...') 局部更新
             图片切换、灯箱、移动菜单、表单校验为纯前端交互
```

- 禁用 JS 时页面仍可浏览（链接跳转、表单可降级提交）。
- 管理后台同样使用 Go 模板 + 原生 JS（fetch 调管理 API），无 SEO 需求。
- 所有面向用户的动态文本经 `html/template` 自动转义，防 XSS。

### 2.2 设计红线（来自 skill 反模式清单 + 需求 UI 规范）

- ❌ emoji 当图标（统一用内联 SVG：Lucide/Heroicons 线条图标）
- ❌ AI 紫粉渐变、过度渐变、夸张特效
- ❌ 布局位移式 hover（只允许 translateY/shadow 微动效）
- ❌ 对比度 < 4.5:1 的文本
- ✅ 全部可点击元素 `cursor: pointer`；状态过渡 150–300ms
- ✅ 焦点态可见（`outline`/ring 3px）；尊重 `prefers-reduced-motion`
- ✅ 触控目标 ≥ 44×44px；无横向滚动；内容不被固定导航遮挡

    │   ├── api.js       # fetch 封装（超时、错误格式解析）
    │   ├── nav.js       # 移动端折叠菜单、粘性导航
    │   ├── gallery.js   # 详情页缩略图切换
    │   ├── lightbox.js  # 大图预览（Esc/方向键关闭）
    │   ├── listing.js   # 产品搜索/筛选/加载更多（调 API）
    │   ├── form.js      # 询价表单校验、提交状态、防重复

CSS 组织约定：BEM 命名（`.product-card__title`）；组件类只在 `components.css`；不使用内联样式（除首屏关键 CSS 内联加速 LCP）。

## 5. 核心交互实现要求

### 5.1 产品图库与灯箱

- 缩略图切换主图：事件委托 + `data-full` 换 `<img src>`，预加载相邻图。
- 灯箱：`<dialog>` 或自建遮罩；支持 Esc 关闭、←/→ 切换、焦点圈定（focus trap）、`aria-modal="true"`、打开时锁 body 滚动。

### 5.2 产品列表增强（listing.js）

- 分类筛选与搜索：fetch `GET /api/v1/products?category=&q=&page=`，替换网格 DOM；同步更新 URL（`history.replaceState`）。
- 加载更多：追加渲染；到达末页隐藏按钮。
- 空结果状态：显示 "No products found" + 清除筛选按钮。
- 图片加载失败：`onerror` 换 `placeholder.webp`（保持 4:5 比例，object-fit: cover，不拉伸变形）。

### 5.3 询价表单（form.js）

- 前端校验：Name/Email/Message 必填，Email 正则；错误就地显示 + `aria-invalid`。
- 提交流程：禁用按钮 + "Submitting…" → `POST /api/v1/inquiries`（JSON）→ 成功显示成功提示并重置；失败显示错误且**保留已填内容**。
- 防重复：提交期间禁用提交按钮；携带一次性 token（后端下发）。
- 表单下方明确信息用途说明与隐私政策链接； honeypot 隐藏字段（`name="website"`，人不可见）。

### 5.4 WhatsApp 链接规范（whatsapp.js + 服务端模板）

- 号码来自后台配置（`/api/v1/site`），规范化：去除 `+`、空格、`-`、`()`，仅保留数字。
- 链接：`https://wa.me/<规范化号码>?text=<encodeURIComponent(询价文本)>`
- 产品页询价文本自动携带：产品名称 + 型号 + 当前页 URL（`location.href`）。
- 移动端 `wa.me` 自动唤起 App；桌面端打开 WhatsApp Web。
- 悬浮按钮固定右下角，避开表单提交按钮区域（`bottom: 88px` 当表单聚焦/在联系页时），不遮挡主要操作。
- 点击仅统计为"点击事件"，不声称代表客户已发送消息。

### 5.5 动画规范

仅允许：区块淡入（IntersectionObserver + `.fade-in`，一次触发）、按钮/卡片 hover 过渡 150–300ms、灯箱缩放淡入、菜单展开过渡。全部包裹：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
}
```

## 6. 响应式布局

| 断点 | 布局 |
|------|------|
| < 768px（手机） | 单列；导航折叠为汉堡菜单；产品卡片单列；悬浮 WhatsApp 常驻 |
| 768–1023px（平板） | 产品 2–3 列；首页优势 2 列 |
| ≥ 1024px（桌面） | 产品 3–4 列；首页 12 栅格分区；导航横向完整展示 |

产品卡片图片统一 `aspect-ratio: 4 / 5` + `object-fit: cover`，保证全站比例一致。

## 7. SEO 与性能

### 7.1 SEO（模板层实现，Go 注入数据）

- 每页独立 `<title>` / `<meta name="description">`（产品页优先用后台填写的 SEO 字段）。
- `<link rel="canonical">` 规范 URL；产品页 `og:title/og:description/og:image/og:url`。
- 全站图片必须填 `alt`（后台可维护 ALT 文本）。
- `sitemap.xml` 与 `robots.txt` 由 Go 生成（后台页加 `noindex`）。

### 7.2 性能

1. 字体：生产环境自托管 woff2 + `font-display: swap`（避免 Google Fonts 在部分地区的延迟）；开发期可用 Google Fonts CDN。
2. 首屏 Banner 图：`<link rel="preload" as="image">`；输出 WebP，`<picture>` 回退 JPEG。
3. 非首屏图片一律 `loading="lazy" decoding="async"` 并带 `width/height` 防 CLS。
4. 视频：默认显示封面图 + 播放按钮，点击后才加载 `<video>`/iframe。
5. 静态资源文件名带内容指纹，`Cache-Control: immutable` 长缓存。
6. 首页不做无意义模块堆叠，控制在 8 个区块内。

## 9. 与后端 API 的对接约定

- 统一走 `/api/v1`；`api.js` 封装超时（10s）、JSON 解析、错误码提取。
- 错误响应格式见《02-开发文档》5.4；前端按 `error.code` 决定提示文案，`error.fields` 映射到对应输入框。
- 公开接口只返回已发布内容，前端不做权限假设。
- 不在 JS 中硬编码联系方式、WhatsApp 号码——一律取自 `/api/v1/site`（服务端模板已注入，JS 仅兜底读取 `data-*` 属性）。
