## 提示词正文（直接投喂）

你是在 SeamCap 项目（义乌无痕棒球帽工厂外贸独立站）中开发**管理后台前端**的资深前端工程师。

### 1. 任务与边界

- 目标：为已完成的 Go 后端（`/api/v1/admin/*`）构建管理后台 SPA，挂载于 `/admin/` 路径。
- 技术栈（已定，不得更换）：**React 18+ + TypeScript（strict）+ Vite 5+ + antd 最新 6.x（本文撰写时 6.6.x）+ react-router-dom 6+**。
  - `npm i antd@latest`；**一切组件 API 以 antd v6 官方文档为准**。注意 v6 相比 v5 的废弃项（如 Drawer 的 `destroyOnClose` 已废弃改用 `destroyOnHidden`、`BackTop` 已移除、部分 Props 类型改用 `GetProps<>` 推导），禁止按 v5 旧 API 抄代码。
  - 主题仍走 v5 延续的 CSS-in-JS 体系：`ConfigProvider theme={{ tokens, components }}`；语言包 `import zhCN from 'antd/locale/zh_CN'`；dayjs 为 antd 内置依赖可直接用。
- 状态管理：只用 React hooks + Context；**不引入 Redux/Zustand/React Query**。请求用统一的 fetch 封装。
- 目录：前端源码放 `web/admin-src/`，构建产物输出到 `web/admin/`（Go 服务静态托管 + SPA fallback，见 §8）。
- **禁止**：
  - 使用 mock 数据冒充功能；所有数据必须来自真实 API。
  - 改动公开站（`web/` 下已有静态首页）与后端 API 语义。唯一允许的后端改动见 §8。
  - 引入额外 UI 库、图表库、CSS-in-JS 库、富文本编辑器（页面 body 用 Textarea+预览，见 5.7）。
  - 后台界面语言为**简体中文**；产品/工艺等**业务内容字段保持英文录入**（面向海外买家），表单用「中文 label + 英文占位」。

### 2. 认证与安全（必须严格实现）

后端认证方式：HttpOnly Cookie（`seamcap_session`）+ CSRF Token 双重校验。

1. `POST /api/v1/admin/login` body `{username, password}` → `200 {data:{admin:{id,username}, csrf_token, expires_at}}`，同时 Set-Cookie。登录成功后：csrf_token 存内存（Context），跳转仪表盘。
2. 应用启动时调 `GET /api/v1/admin/me` 恢复会话；`200` 返回 `{data:{admin, csrf_token}}`（刷新页面后从 me 重新取 csrf 存入 Context）；`401` → 跳登录页。
3. **所有写请求（POST/PUT/DELETE）必须带请求头 `X-CSRF-Token`**；缺失/错误后端返回 `403 {error:{code:"FORBIDDEN", message:"Missing or invalid X-CSRF-Token"}}`。
4. 任何接口返回 `401` → 清空本地状态并跳转登录页（fetch 封装里统一处理）。
5. 退出：`POST /api/v1/admin/logout` → 跳登录页。
6. 登录限流：同 IP 或同账号 5 次/5 分钟超出返回 `429`，登录页把 `error.message` 原样提示；前端不做假的倒计时锁定。

### 3. 请求封装约定

- 统一 fetch 封装 `request()`：自动带 JSON 头（multipart 除外）、自动带 `X-CSRF-Token`、自动解包 `{data, pagination}`、统一错误处理、上传类请求不设 `Content-Type`（浏览器自动带 boundary）。
- 后端错误结构（固定）：`{error:{code, message, fields?}}`；code ∈ `VALIDATION_ERROR(400)|UNAUTHORIZED(401)|FORBIDDEN(403)|NOT_FOUND(404)|CONFLICT(409)|PAYLOAD_TOO_LARGE(413)|RATE_LIMITED(429)|INTERNAL(500)`。
- `fields` 是字段级错误 map：**必须用 `form.setFields()` 把 fields 映射到对应表单项**。slug 冲突 409 时 `fields.suggestion` 提供建议值：在 slug 项下方显示「已被占用，建议：xxx」并附「采用建议」按钮（一键回填）。
- 分页响应：`{data:[...], pagination:{page, per_page, total}}`，表格分页参数同名回传。
- 列表为空显示 antd `Empty`；请求中表格 `loading`、卡片 `Skeleton`；禁止用假数据填充空态；错误态 `Alert` + 重试，不得渲染成「暂无数据」。

### 4. 设计规范（Ant Design Premium UI）

- 主题：`ConfigProvider` tokens 集中定义（`theme.ts`），禁止散落硬编码色值。
  - 品牌主色 `#0369A1`（主按钮/链接/选中态）；深海军蓝 `#0F172A` 仅用于标题文字与标识。
  - 页面底 `#F6F7F9`、卡片面 `#FFFFFF`、边框 `#E3E7ED`；正文 `#202735`、次要 `#626C7B`、弱化 `#9299A5`。
  - 语义色：成功 `#14866D` / 警告 `#B7791F` / 错误 `#D9535D` / 信息 `#4384C5`。
- 布局：左侧**浅色** Sider（可折叠；选中项品牌 tint 底 + 左侧 3px 主色指示条，不满铺饱和色）；顶栏含面包屑 + 管理员下拉（修改密码/退出登录）；内容区卡片圆角 8px、1px 边框、无重阴影；卡片内边距统一 20-24px。
- 密度：企业级紧凑，4px 间距基数；表格行高约 44px、表头约 42px；表单统一 `vertical` 布局。
- 状态表达必须**色 + 文字**双通道（Tag 带文字），不得只用颜色。
- 动效克制：160-220ms ease-out；hover 只变边框/底色；不做数字滚动、弹跳、整页闪烁；尊重 `prefers-reduced-motion`。
- 可访问性：图标按钮配 Tooltip/aria-label；焦点态可见；弹窗开关管理焦点。

### 5. 页面清单与 API 映射（逐页实现，字段名照抄）

**通用列表约定**：筛选区在表格上方一行（`Input.Search`/`Select`/`DatePicker.RangePicker`），300ms 防抖即查；分页显示 total；行操作统一「编辑 + 更多下拉」；删除一律 `Popconfirm` 二次确认。

#### 5.1 登录页 `/admin/login`
- 居中卡片：SeamCap 标识、用户名、`Input.Password`、登录按钮（loading 防重复提交）。
- 401 →「用户名或密码错误」；429/500 → 显示后端 message；成功跳 `/admin/`。

#### 5.2 仪表盘 `/admin/`
- `GET /admin/dashboard` → `{products:{published,draft,archived}, craftsmanship:{total,published}, inquiries:{new}, recent_inquiries[5], recent_products[5]}`
- 统计卡一行（Statistic）：已发布产品 / 草稿产品 / 已归档产品 / 工艺数 / **新询价**（新询价卡用错误色 tint 强调，点击跳询价列表并自动带上状态筛选）。
- 两栏表格：最近询价（姓名/邮箱/产品快照/状态 Tag/时间，点击开详情抽屉）、最近更新的产品（40px 主图缩略/名称/SKU/状态/更新时间，点击进编辑页）。

#### 5.3 产品管理 `/admin/products`（核心页面）
- 列表：`GET /admin/products?q&category_id&status&page&per_page`（含草稿）。
  - 列：主图（40px 圆角缩略，无图占位）、名称、SKU、分类、状态 Tag（draft 灰 / published 成功 / archived 警告）、精选（Star 实/空）、更新时间。
  - 筛选：关键词、分类（`GET /admin/categories` 下拉）、状态。
  - 行操作：编辑、复制（`POST /admin/products/{id}/duplicate`，成功刷新并 message 新 slug）、删除。
  - 工具栏：「新建产品」主按钮。
- 新建/编辑：**整页表单**（字段多，不用弹窗），顶部 Tabs：
  1. 基础信息：name*、sku、slug（留空自动生成；409 按 §3 展示建议）、category_id（Select，可空）、status（Radio：draft/published/archived）、is_featured（Switch）、sort_order（InputNumber）。
  2. 图与视频：main_image_id（媒体单选器组件）、video_url。
  3. 描述（英文）：short_desc、detail_desc（Textarea）。
  4. 规格：material、cap_shape、colors、sizes、customization（文本，占位提示逗号分隔）。
  5. 画廊：`PUT /admin/products/{id}/media` body `{items:[{media_id, role, sort_order}]}`。媒体选择器多选添加 → 缩略图网格支持上移/下移排序 → 每张可设角色（main/gallery/detail，**最多一个 main**，设为 main 即同步主图）→ 保存整表提交。校验错误 `fields["items[0].media_id"]` 定位到对应卡片提示。
- 校验与后端一致：name 必填≤200、sku≤100、video_url/seo_title≤200、seo_desc≤500；后端 400 `fields` 直接映射到表单项。

#### 5.4 分类管理 `/admin/categories`
- `GET /admin/categories`（全量数组，含 product_count）、`POST`、`GET/PUT /admin/categories/{id}`。
- 字段：name*、name_en、slug（留空按 name_en→name 自动生成）、description、image_id（媒体单选器）、sort_order、status（active/inactive）。
- 删除三策略交互：`DELETE /{id}` → 若 `409`（`fields.product_count` 有值），弹 Modal 二选一：**「迁移到…并删除」**（Select 目标分类 → `DELETE /{id}?mode=reassign&to={id}`）或 **「仅停用」**（`?mode=archive`）；无关联直接删除。

#### 5.5 媒体库 `/admin/media`
- 网格卡片流（图片缩略 160px；视频显示占位+播放角标），`GET /admin/media?q&page&per_page`。
- 上传：`Upload.Dragger` 多文件 + `customRequest` → `POST /admin/media`（multipart：`file`、`alt_text`）。前端预校验：图片≤10MB、视频≤500MB、类型 jpg/png/webp/avif/mp4；`413` 提示超限；类型错误以后端 magic number 校验为准（前端校验仅体验优化）。
- 卡片操作：预览（Modal 大图/`<video>` 播放）、复制 URL（`/uploads/...` 相对路径拼接 `location.origin`）、编辑 ALT（`PUT /admin/media/{id}` JSON `{alt_text}` 或 multipart）、替换文件（multipart 同 mime，后端 400 时提示不匹配）、删除。
- 删除 `409`：Modal 列出 `fields.reference_count` 与 `fields.references`（如 `products.main_image; products.gallery`），仅「知道了」。

#### 5.6 工艺管理 `/admin/craftsmanship`
- 列表 `GET /admin/craftsmanship`（全量）：标题、slug、状态 Tag（draft/published/hidden）、排序、更新时间。
- 编辑字段：title*、slug、summary、body、cover_image_id（媒体单选）、video_url、sort_order、status、seo_title、seo_desc；画廊 `PUT /admin/craftsmanship/{id}/media` `{items:[{media_id,sort_order}]}`（无角色概念）。删除 `Popconfirm`。

#### 5.7 页面管理 `/admin/pages`
- 列表 `GET /admin/pages`（slug/title/status/更新时间）。
- 编辑 `GET/PUT /admin/pages/{slug}`：title*、slug（只读）、body（**受控 HTML**：等宽字体 Textarea + 右侧预览 Tab；顶部 Alert 说明「仅允许白名单标签，script/iframe/事件属性将被服务端过滤」）、status、seo_title、seo_desc。

#### 5.8 首页内容 `/admin/home`
- `GET/PUT /admin/home` 单页表单：
  - Hero：hero_title、hero_subtitle、hero_image_id（媒体单选）、hero_video_url；
  - CTA：cta1_text/cta1_url、cta2_text/cta2_url；
  - factory_intro、contact_blurb、footer_text；
  - advantages：`Form.List` 动态数组（title/desc/image 媒体单选，≤12 项，可增删）；
  - process_steps：`Form.List`（step/desc，≤12 项）。
  - 保存后 message「首页内容已更新，前台立即生效」。

#### 5.9 站点设置 `/admin/settings`
- `GET/PUT /admin/settings`（KV map）。分组表单：
  - 基础：site_name、logo_url（媒体单选器回填 URL）；
  - 联系：whatsapp（占位 `+86 133 8861 4562`）、whatsapp_text、email、phone、address、map_link；
  - 社交链接：social_links 为 JSON 字符串 —— UI 做**动态 KV 行编辑器**（label+URL），提交时序列化为 JSON；后端 400 `fields.social_links` 映射提示；
  - SEO：seo_title、seo_desc。
  - 保存后仅提交被修改的键（PUT map）。

#### 5.10 询价管理 `/admin/inquiries`（核心页面）
- 列表 `GET /admin/inquiries?q&status&from&to&page&per_page`：
  - 筛选：关键词（姓名/公司/邮箱/产品快照）、状态多选 Select、提交时间范围。
  - 列：ID、姓名+公司、邮箱、WhatsApp/电话、产品快照（名称+SKU 两行，无快照显示「—」）、状态 Tag、邮件通知 Tag（sent 成功 / failed 失败 / pending 灰 / skipped 灰）、时间。
  - 工具栏：「导出 CSV」（`GET /admin/inquiries/export` 同筛选参数，浏览器直接下载，后端已带 BOM）。
- 详情抽屉（width 640）：
  - `Descriptions`：联系方式、source_page、estimated_qty、customization、IP/UA、产品快照（product_id 为 null 显示「产品已删除」）；
  - message 完整展示（`pre-wrap`）；
  - 状态操作：Select 改状态（`PUT /admin/inquiries/{id}` `{status}`，可选 new/following/replied/completed/spam）+ 内部备注 Textarea（`{internal_note}`）；
  - 邮件重发按钮（pending/failed 时显示）：`POST /admin/inquiries/{id}/resend-notify`；
  - 事件时间线：`events[]` 用 `Timeline`（created/status_changed/note/notify 区分图标，显示 from→to、时间）；
  - 删除：Popconfirm（文案注明「询价与事件历史将一并删除」）。

#### 5.11 审计日志 `/admin/audit-logs`
- `GET /admin/audit-logs?limit=200`：只读表格（时间/操作人/动作/实体/详情/IP），倒序。

#### 5.12 修改密码
- 顶栏用户下拉 → Modal：current/new/confirm；前端校验新密码≥10 位且含字母数字（与后端一致）；成功 message「密码已修改，其他会话已失效」。

### 6. 工程要求

- 目录：`web/admin-src/src/{main.tsx, App.tsx, api/(client.ts, types.ts), context/AuthContext.tsx, layouts/AdminLayout.tsx, pages/(login/, dashboard/, products/, categories/, media/, craftsmanship/, pages/, home/, settings/, inquiries/, audit/), components/(MediaPicker/, MediaUploader/, StatusTag/, PageHeader/), theme.ts}`。
- `api/types.ts` 定义全部 TS 类型（Product/Category/Media/Craftsmanship/PageContent/HomeContent/Inquiry/InquiryEvent/AuditLog/Pagination/ApiError/CSRFResponse 等），字段名与后端 JSON 完全一致（snake_case）。
- TypeScript strict 全通过；`npm run build` 零报错；vite `base:'/admin/'`，`build.outDir:'../web/admin'`。
- 开发模式：`npm run dev` 端口 5173，`server.proxy['/api'] → http://localhost:8080`（changeOrigin:false 以便 Cookie 同源透传）。
- 路由守卫：会话恢复前全局 `Spin`；`AuthContext` 提供 `{admin, csrf, login, logout, refresh}`。
- 组件复用：MediaPicker（单选/多选，Drawer 内网格 + 搜索 + 上传入口）、StatusTag（产品/询价/邮件三套映射）、PageHeader（标题+主操作）。

### 7. 验收标准

1. 登录/登出/改密全流程可用；刷新页面会话保持；401 自动跳登录。
2. 产品从新建（草稿）→ 上传主图与画廊 → 发布 → 公开 API `GET /api/v1/products` 可见 → 复制 → 删除，全链路无控制台报错。
3. slug 冲突出现 409 建议值并可一键采用；分类删除出现三策略弹窗并可完成迁移。
4. 媒体上传（含 10MB 大图与超限文件）行为正确；被引用媒体删除显示引用来源。
5. 询价列表筛选/详情抽屉/状态流转/内部备注/事件时间线/CSV 导出全部可用；`email_notify_status=skipped`（未配 SMTP）正确显示灰色。
6. `npm run build` 产物由 Go 服务在 `/admin/` 正常承载，刷新任意子路由不 404（SPA fallback）。
7. 全程无 mock 数据；所有列表/表单数据与 SQLite 数据库一致。

### 8. 后端配合改动（仅此一处，已获准）

Go 侧为承载 SPA 需小改 `cmd/server/main.go`：
- 新增静态托管：`/admin/` 与 `/admin/assets/*` 指向 `web/admin/`（带 Cache-Control，assets 指纹文件长缓存，index.html 不缓存）；
- `/admin/*`（非 `/api` 前缀、非静态文件命中）统一 fallback 到 `web/admin/index.html`；
- 原有 JSON 404 行为仅保留给 `/api/*`。
- 注意：管理页响应继续带 `X-Robots-Tag: noindex`、`X-Frame-Options: DENY`（现有 AdminSecurityHeaders 语义扩展到 HTML 页面）。

## 实施顺序建议（给实现者）

1. 脚手架 + 主题 tokens + 请求封装 + 认证流（§2/§3）→ 登录页与 AdminLayout 骨架。
2. 仪表盘 + 产品列表/编辑（含 MediaPicker/MediaUploader 组件）——先打通最重链路。
3. 分类 → 媒体库 → 工艺 → 页面 → 首页 → 设置。
4. 询价管理 → 审计日志 → 修改密码。
5. §8 后端 fallback 改动 + 生产构建联调（`go build` + 浏览器全链路走查）。
6. 每步以 `npm run build` 零报错为过点；最后按 §7 验收清单逐项核对。
