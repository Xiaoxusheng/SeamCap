# 02 · 项目开发总文档

> 项目：义乌无痕棒球帽源头工厂外贸独立站（SeamCap）
> 性质：B2B 产品展示官网（无购物车、无支付、无订单系统）

---

## 1. 项目概述

### 1.1 目标

为义乌无痕棒球帽源头工厂建设面向海外采购商的独立站：展示产品样品、工艺细节与工厂实力，通过 WhatsApp / 询价表单获取客户线索。核心是**产品展示 + 内容管理 + 询价收集**，不做电商交易。

### 1.2 核心功能范围

| 模块 | 说明 |
|------|------|
| 前台展示 | 首页、产品列表/详情、工艺、关于我们、联系我们、隐私政策、404 |
| 管理后台 | 登录、仪表盘、产品/分类/媒体/工艺/页面/首页内容/设置/询价管理、SEO 设置、审计日志、备份 |
| Go 后端 | 公开 API、管理 API、认证、文件上传、邮件通知、SEO 数据、日志与备份 |
| 联系能力 | 全站 WhatsApp 入口（后台配置号码）、询价表单、邮件通知 |

### 1.3 明确不开发（第一期）

购物车、在线支付、电商订单、物流跟踪、会员中心、用户注册、库存管理、ERP、复杂 CRM、多级审批、实时在线客服、微服务集群、复杂 BI、多租户 SaaS。

## 2. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | 原生 HTML5 / CSS3 / JavaScript（零框架） | 需求硬性要求；轻量可控；避免模板授权费 |
| 页面渲染 | **Go 服务端模板渲染（html/template）+ JS 渐进增强** | 需求 5.8：SEO 优先由服务端输出完整 HTML；交互（搜索/筛选/加载更多）用 fetch 调 API 增强 |
| 后端 | Go 1.22+，标准库 `net/http` + Chi v5 轻量路由 | 模块化单体；依赖少 |
| 数据库 | SQLite（`modernc.org/sqlite` 纯 Go 驱动）+ 版本化迁移 | 第一期零运维；repository 层隔离，预留 PostgreSQL 迁移 |
| 密码哈希 | Argon2id（`golang.org/x/crypto`） | 安全要求 4 |
| 日志 | 标准库 `log/slog` 结构化日志 | 无额外依赖 |
| 邮件 | 标准库 `net/smtp`（STARTTLS/SSL）封装 | 凭据走环境变量；失败不影响询价落库 |
| 部署 | Linux + systemd + Caddy（或 Nginx）+ HTTPS | 自动签发证书，配置最简 |

**设计系统基线**：由 ui-ux-pro-max skill 生成（`design-system/seamcap/MASTER.md`）——深海军蓝 `#0F172A` / 米白 `#F8FAFC` / CTA 蓝 `#0369A1`，Plus Jakarta Sans 字体，"信任权威 + 转化"页面模式。

## 4. 数据库设计（14 张表）

> 完整字段与 DDL 见《04-后端开发文档》第 4 节。此处为总览。

| # | 表名 | 用途 | 关键约束 |
|---|------|------|---------|
| 1 | admin_users | 管理员 | 密码 Argon2id 哈希 |
| 2 | sessions | 会话 | token 仅存哈希；expires_at 索引 |
| 3 | products | 产品 | slug UNIQUE；status 索引；category_id FK |
| 4 | product_categories | 分类 | slug UNIQUE |
| 5 | product_media | 产品↔媒体关联 | 级联策略明确，保留历史询价快照 |
| 6 | craftsmanship | 工艺内容 | status + sort_order 索引 |
| 7 | craftsmanship_media | 工艺↔媒体关联 | |
| 8 | pages | 普通页面（关于/隐私等） | slug UNIQUE |
| 9 | home_content | 首页内容（单行） | id=1 |
| 10 | site_settings | 站点配置 KV | key 主键 |
| 11 | inquiries | 客户询价 | status/created_at 索引；冗余 product_name 快照防产品删除丢信息 |
| 12 | inquiry_events | 询价状态历史 | inquiry_id FK |
| 13 | media_assets | 上传文件元数据 | 引用计数检查后再删文件 |
| 14 | audit_logs | 后台审计日志 | admin_id、created_at 索引 |

要点：产品 slug 唯一；询价保存产品名称/型号**快照**，产品删除不影响历史询价；删除媒体前检查引用关系；全部查询参数化。

## 5. REST API 概览（前缀 `/api/v1`）

### 5.1 公开接口

| 方法+路径 | 用途 |
|-----------|------|
| GET /site | 站点信息与联系方式 |
| GET /home | 首页内容 + 精选产品 |
| GET /products | 产品列表（关键词/分类/分页/排序，仅已发布） |
| GET /products/{slug} | 产品详情（仅已发布） |
| GET /categories | 公开分类 |
| GET /craftsmanship | 已发布工艺列表；/craftsmanship/{slug} 详情 |
| GET /pages/{slug} | 已发布普通页面 |
| POST /inquiries | 提交询价（校验+限流+反垃圾） |
| GET /health | 健康检查 |

### 5.2 认证接口

`POST /admin/login`、`POST /admin/logout`、`GET /admin/me`、`POST /admin/change-password`

### 5.3 管理接口（全部需认证）

dashboard、products（CRUD+复制+精选标记）、categories（CRUD）、media（列表/上传/替换/删除）、craftsmanship（CRUD）、pages/{slug}（读/改）、home（读/改）、settings（读/改）、inquiries（列表/详情/状态/备注/删除/CSV 导出）、backup（触发备份）。

### 5.4 统一响应格式

```json
// 成功
{ "data": { ... } }
{ "data": [ ... ], "pagination": { "page": 1, "per_page": 20, "total": 87 } }

// 失败
{ "error": { "code": "VALIDATION_ERROR", "message": "Invalid email address",
             "fields": { "email": "must be a valid email" } } }
```

状态码规范：200 成功 / 201 创建 / 400 参数错 / 401 未认证 / 403 越权 / 404 不存在 / 409 冲突（如 slug 重复）/ 413 体积超限 / 429 限流 / 500 内部错误（不暴露堆栈）。

## 6. 开发阶段计划

### 第一阶段：项目基础与前台展示

**任务**：目录骨架 → Go 服务基础（chi 路由/日志/配置/健康检查）→ 迁移脚本与 14 张表 → repository/service 基础 → 前台 6 个页面 SSR（首页/产品列表/产品详情/工艺/关于/联系 + 404）→ 设计系统 CSS → 公开 API → WhatsApp 功能 → 响应式。

**验收**：页面正常显示；产品数据来自后端；手机与桌面布局可用；产品详情 URL 为 `/products/{slug}/`。

### 第二阶段：管理后台

**任务**：登录/退出/改密（Argon2id + 会话 + 登录限流 + 安全 Cookie）→ 仪表盘（真实数据库统计）→ 产品管理（列表/搜索/筛选/分页/增删改查/复制/状态切换/精选/排序）→ 分类管理 → 媒体管理（上传/替换/删除/排序/ALT/安全校验）→ 工艺/页面/首页内容管理 → 站点设置。

**验收**：管理员通过后台新增产品、上传图片、修改英文文案后，官网同步显示。

### 第三阶段：客户询价与安全

**任务**：询价表单（前端校验+后端二次校验+提交状态+防重复）→ `POST /api/v1/inquiries`（字段校验/限流/反垃圾/落库）→ 询价后台（列表/搜索/筛选/详情/状态流转/内部备注/CSV 导出/状态历史）→ 邮件通知（SMTP 配置、失败不丢数据、失败可重发）→ 文件上传安全加固 → CSRF/CORS/安全头。

**验收**：客户成功提交询价；后台可查看处理；邮件通知实际测试通过。

### 第四阶段：上线部署与交付

**任务**：域名 DNS → Caddy/Nginx + HTTPS → systemd 服务 → 备份脚本（数据库 + uploads）→ SEO 终检（sitemap/robots/canonical/OG）→ 真实访问测试（含海外网络）→ 维护文档。

**验收**：真实域名 HTTPS 可访问；主要页面、图片、视频、询价表单、WhatsApp 功能正常；备份可恢复。

> 每阶段结束：执行 `go build` + `go test ./...`，输出"已完成内容 / 测试结果 / 遗留问题"总结。未完成的功能明确说明，不伪装完成。

## 7. 安全要求清单（贯穿所有阶段）

1. HTTPS（Caddy 自动证书）；2. 管理接口统一认证 + 后端权限校验；3. Argon2id 密码哈希；4. 登录限流（IP+账号维度）；5. 全部 SQL 参数化；6. 输出转义防 XSS（html/template 自动 + 富文本白名单过滤）；7. 管理后台 CSRF 防护；8. 上传白名单 + 真实格式嗅探 + 大小限制 + 安全文件名 + 路径穿越防护；9. 询价接口 IP 限流 + honeypot 反垃圾；10. Cookie `HttpOnly + Secure + SameSite=Lax`；11. 生产环境不暴露堆栈/内部路径；12. 凭据仅存环境变量，不进 Git；13. 防越权（ID 校验归属）；14. 数据库与 uploads 定期备份并演练恢复。

## 9. 部署方案概要

```
deploy/
├── Caddyfile                  # 反代 + 自动 HTTPS + 静态资源缓存/压缩
├── nginx.conf                 # Nginx 备选方案
├── seamcap.service            # systemd unit
├── backup.sh                  # SQLite .backup + uploads 打包
└── restore.md                 # 恢复步骤
```

要点：www 与根域名统一跳转；静态资源长缓存 + 指纹文件名；图片 WebP 优先；部署不覆盖 `data/` 与 `uploads/`；上线前完成真实域名 HTTPS 与海外访问实测，未实测不得声称已上线。
